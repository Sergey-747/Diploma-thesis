# Требования к аппаратно-программно обеспечению тестового стенда

## 1. Требования к аппаратному обеспечению (Hardware)
UI-тестирование с использованием **Selenium WebDriver** напрямую зависит от системных ресурсов компьютера, так как каждый запуск теста инициализирует полноценный физический процесс браузера **Google Chrome** (или Chromium), активно потребляющий оперативную память и ресурсы центрального процессора.

В таблице 1.1 приведены минимальные (для запуска изолированных тестов) и рекомендуемые (для параллельного выполнения тестов и генерации графической отчетности) аппаратные характеристики.

### Таблица 1.1 — Требования к аппаратному обеспечению АРМ тестировщика

| Аппаратный компонент | Минимальные требования | Рекомендуемые требования |
| :--- | :--- | :--- |
| **Центральный процессор (CPU)** | Двухъядерный процессор с тактовой частотой от 2.0 ГГц (например, Intel Core i3 / AMD Ryzen 3). | Четырехъядерный (и более) процессор с архитектурой x86-64 / ARM64, частота от 3.0 ГГц (Intel Core i5 / AMD Ryzen 5 / Apple M-серия). |
| **Оперативная память (RAM)** | Не менее 8 ГБ. При меньшем объеме возможны падения тестов по ошибке *Out of Memory* из-за утечек памяти браузера. | 16 ГБ (и более) для обеспечения стабильной работы при параллелизации потоков тестирования. |
| **Дисковая подсистема (Storage)** | HDD-накопитель, не менее 5 ГБ свободного дискового пространства для хранения библиотек и логов. | Высокоскоростной накопитель SSD (NVMe), не менее 10 ГБ свободного места для быстрого кэширования профилей браузера. |
| **Сетевой интерфейс (Network)** | Модем / Сетевая карта с пропускной способностью от 10 Мбит/с (для базовых текстовых запросов). | Широкополосный доступ в Интернет от 50 Мбит/с (необходим для корректного замера таймаутов при загрузке тяжелых страниц). |

## 2. Требования к программному обеспечению (Software)
Программная среда тестового стенда должна обеспечивать корректную интерпретацию кода на языке **Python** и бесконфликтное взаимодействие Selenium WebDriver с системными библиотеками операционной системы.

Базовый состав программного обеспечения АРМ, применяемый при тестировании:
Операционная система: Microsoft Windows 10
Среда интерпретации и исполнения кода: Python версии 3.14. 
Инструментальное ПО (Среда разработки): Редактор кода VS Code (Visual Studio Code) с установленным расширением Python.
Утилиты управления зависимостями: Менеджер пакетов pip (встроен в Python) для развертывания внешних библиотек автоматизации.

## 3. Спецификация используемых библиотек и версий ПО
Для фиксации состояния тестового стенда и обеспечения воспроизводимости результатов тестирования на сторонних компьютерах, программные зависимости жестко зафиксированы в конфигурационном файле проекта. Спецификация используемого ПО приведена в таблице 3.3.
Таблица 3.1 — Спецификация версий программных компонентов
| Наименование компонента / Библиотеки | Назначение в проекте | Зафиксированная версия |
| :--- | :--- | :--- |
| **Python** | Базовый язык программирования, интерпретатор тестовых скриптов. |	v3.14.x |
| **Selenium WebDriver** | Библиотека автоматизации действий пользователя в веб-браузере, инструмент прямого управления DOM-моделью сайта. | v4.22.x (и выше) |		
| **Google Chrome/ Chromium** | Целевой веб-браузер, в среде которого осуществляются прогоны пользовательских интерфейсных сценариев. | Стабильная версия (Stable Build) |
| **unittest** | Системный встроенный фреймворк для организации структуры тестов, логирования результатов и применения фикстур. | Встроенный модуль (Standart Library) |

## 4. Запуск разработанного программного комплекса
Для обеспечения воспроизводимости разработанного программного комплекса верификации на сторонних рабочих станциях и исключения конфликтов версий (эффект "dependency hell"), все внешние программные библиотеки проекта были строго зафиксированы в конфигурационном файле requirements.txt. Использование декларативного описания зависимостей позволяет автоматизировать процесс развертывания тестового стенда. Установка целевого пакета selenium фиксированной версии 4.22.x гарантирует стабильную работу встроенных механизмов автоматического скачивания веб-драйверов (Selenium Manager) и инвариантность окружения при интеграции в автоматизированные контуры CI/CD.

## 5. Инструкция для запуска проекта.
1.	Скачать файлы тестов в локальную папку.
2.	Открыть терминал в папке проекта и установить зависимости:
3.	pip install -r requirements.txt
4.	Запустить тестовый набор:
5.	python test_**.py
